## Proyecto WebAppPoliMusicV2 (ASP.NET Web Forms, C#, .NET Framework 2.0)

Análisis inicial del proyecto: arquitectura de 3 capas (Entities / BLL / DAL) + Util, y carpetas de contenido
(UserImages, PlaylistImages, SongFiles). Es la migración de `../webapppolimusicv1_asp` (ASP clásico, ya completo).

Estado: solo el módulo de autenticación está implementado (Login / SignUp / Logout).
Pendiente detectado: `Song.aspx` y `DesktopAdmin.aspx` están referenciados pero no existen; no hay Master Page ni CSS.

### Trabajo realizado
- Creado `DAL/Song.cs` con CRUD sobre `TBL_SONG` (Save, Read, Update, Delete) + `CheckExistSong`,
  replicando el patrón exacto de `DAL/User.cs` (ADO.NET puro, `using`, `AddWithValue`, `ExecuteNonQuery`, `DataTable`).
- Creado `Entities/Song.cs` (POCO: ID, SongName, SongPath, Plays) — necesario para que el DAL compile.
- Ambos archivos agregados al `.csproj` (antes `DAL/Song.cs` existía vacío y NO estaba incluido en la compilación).
- Creado `BLL/Song.cs` (48 líneas): fachada que delega a `DAL.Song` (Save, Read, Update, Delete, CheckExistSong)
  + `ValidationsDuplicated(song)` → "Song already registered!". Agregado al `.csproj`.

### Página Song.aspx (CRUD + reproductor)
- Creados `Song.aspx`, `Song.aspx.cs`, `Song.aspx.designer.cs`; registrados en el `.csproj`
  (`Content` + 2 `Compile` con `DependentUpon`).
- Diseño propio: tema oscuro estilo Spotify (verde #1db954/#1ed760, tracklist con hover, play circular)
  + detalles Apple (topbar con backdrop-filter, tipografía -apple-system, radios 18px, glass).
  Todo el CSS va inline en un `<style>` dentro del `.aspx` (el proyecto no tiene CSS externo ni Master Page).
- CRUD: el panel de administración solo se renderiza si `UserType == ID_USER_ADMIN`; la columna
  Editar/Eliminar se oculta en `RowDataBound` para usuarios normales. Un solo formulario sirve para
  alta y edición (`hfSongID`: 0 = insertar, >0 = actualizar).
- Reproductor: `<audio>` HTML5 renderizado desde un `Literal` con `ResolveUrl(SONG_PATH)` + `autoplay`.
- `DeleteSong` captura `SqlException` porque TBL_SONG tiene FKs desde TBL_TRACKLIST / TBL_PLAYER / TBL_PLAYLIST_SONG.
- Se agregó `IncreasePlays(int)` a `DAL/Song.cs` (usa `ISNULL([PLAYS],0) + 1`) y a `BLL/Song.cs`.
- `Web.config`: `songFolderPath` pasó de `../songFiles/` a `~/SongFiles/` (el `../` resolvía fuera de la app).
- `PLAYS` es NULLable: la página agrega la columna calculada `PLAYS_TEXT` al DataTable antes de enlazar.



### Esquema de referencia
`TBL_SONG (ID_SONG int IDENTITY PK, SONG_NAME varchar(50) NOT NULL, SONG_PATH varchar(255) NOT NULL, PLAYS int NULL)`
Esquema completo en `../webapppolimusicv1_asp/PoliMusic/SQL/01_BDD_PoliMusic.sql` (9 tablas).
`TBL_SONG` tiene FKs desde TBL_TRACKLIST, TBL_PLAYER y TBL_PLAYLIST_SONG → el Delete puede violar FK.

### Convenciones del proyecto
- DAL: clase con `private string strConnectionString`, constructor que recibe el conn string, SQL en variable `sentence`.
- Código debe ser compatible con C# 3.0 / .NET Framework 2.0: sin interpolación, sin expression-bodied members.
- Connection string: `BDD_PoliMusicConnectionString` en Web.config.
- El entorno bloquea `csc.exe` y `msbuild`: no se puede compilar desde el agente, solo editar y validar por lectura.
